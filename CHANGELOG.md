# am-lang-core changelog

The runtime and standard library every AmLang program links. Core is released
with the compiler and carries the same version; changes that need a compiler
change are also in the compiler's `docs/releases/CHANGELOG.md`. Redmine numbers
are issues in the private tracker.

## [0.16.0] - Unreleased

Changes since 0.15.0. Needs amlc 0.16.0.

### Added

- **GenericFieldInitTests** (2026-11-17, #406). Field initializers that name a type parameter in a generic class, as a program checking values: `var items: List<T> = new List<T>()` and `var named: HashMap<String, T> = new HashMap<String, T>()` in `GfBox<Int>` and `GfBox<String>`, adding and reading back, a separate list per instance, a plain initializer beside them; and a generic subclass `GfSub<T> : GfBase<T>` with a `List<T>` initializer in both and an `Int` one in the base, for `Int` and `String`. v2 rendered the erased `Am_Collections_List_f_List_0` (a gcc error); passes under v1 and v2.
- **ParenGenericReceiverTests** (2026-11-17, #402). Calls on a parenthesised generic receiver, as a program checking the values: `(l).add(5)`, `(l).get(0)` and `(l).getSize()` on a `List<Int>` and a `List<String>`, as statements and as arguments (into an Int parameter and an Any one); `(m).set`/`get`/`containsKey` on a `HashMap<String, Int>`; a user `PgBox<Int>` and `PgBox<String>`; through a cast, `(any as List<Int>).add(11)`; and through a member and a call, `(h.items).add(21)`, `(h.box()).put(3)`. Passes under v1 and v2.
- **NonNullChainTests** (2026-11-17, #401, #386). A `!!` inside a statement's receiver chain, as a program checking values and side effects: `a.next!!.count` read in a statement chain, as an argument and in a `var`; `a.next!!.count = 5`, `++`, `--`, `+=` and a String `+=`; `a.next!!.bump()` as a statement and an argument; `a!!.bump()`, `a!!.next!!.count++` and `a!!.next!!.count` on a local; the same on a local inferred from a static; `a.self()!!.bump()` after a call; `i!!.toString()`, `i!!.hash()` on an `Int?` and `color!!.getValue()` on an enum `?`, as statements and in expressions; `c!!.resume()` on an inferred `Continuation?` local (#386); and a NullAssertionError for null through each form (`none!!.bump()`, `a.next!!.bump()`, `a.next!!.count++`, `a.next!!.count = 4`, `a.nextOf()!!.bump()`). Passes under v1 and v2.
- **ParenReceiverTests** (2026-11-17, #398). Statements that start with a parenthesised receiver, as a program, each checking the call's side effect: `(new X()).f()`, `(p).f()`, `(b as Child).f()`, `(c as Base).f()` and `(b).f()` (the override runs), an inherited function through a cast, `(p.b).g()`, chains `(new X()).g().f()` and `(c).g().g().name()`, assignments `(c).field = 5`, `(b as Child).field = 6`, `(c.child!!).count++`, `(c).field += 10`, a call followed by a next-line `(p).f()` (two statements, #18), `(s).length()`, `("x" + s).length()` and `(a * b).toString()`. v2 dispatched these on the call's return type and failed in gcc; passes under v1 and v2.
- **LoopJumpTests** (2026-11-17, #387). A plain `break`/`continue` in an unlabeled `for` (until and to), `loop` and `each` (over `Int[]` and a `List`) as a program: inside `if` blocks holding objects, two `if` blocks deep, alone in an `if` block (the raw C jump v2 keeps), each with an allocation count; inside `try`/`finally` (counting the finally runs), nested `try`/`finally` (both run), a `break` in a `catch`, and a `return` and a `throw` in a `catch` with a `finally`; in suspend functions with a suspension in the `try` and in the `finally`, nested finallies over a `List`, a `catch`, and a `continue@outer` out of an inner loop, with allocation counts. v2 leaked the `if` blocks' objects and skipped the finally blocks; passes under v1 and v2.
- **SuspendLoopTests** (2026-11-17, #384, #385). A suspend function that parks inside each loop form, run as a program: nested `for` (to and until), a computed bound and a call bound, two loops with the same counter name, `each` over `Int[]`, `String[]`, a `List` and a `HashSet`, `each` inside `for`, `loop` and `while` with locals declared in the body before and after the suspension, plain `break` and `continue`. Each case checks its result, then runs five more times with an allocation count around them. Needs amlc 0.16.0 (v1 or v2).
- **LoopLabelTests** (2026-11-17, #164). Labeled loops (`outer@ for (...)`, `break@outer`, `continue@outer`) as a program: nested for/while/loop/each in both forms, to and until ranges, three levels, jumps out of a try (the finally runs, and a plain break or continue there skips the rest of the loop body, which v2 ran), inside switch and when, a label named like a local or the loop variable, a lambda reusing the outer label, a suspend function that parks inside the loops (while and, since #384, for; with an allocation count since #385), and an allocation count that shows the objects of the left loop bodies are released. Needs amlc 0.16.0 (v1 or v2).
- **InferredNullableLocalTests** (2026-11-17, #383). A local without a type initialised from a nullable value is nullable: from a call returning `Int?`, a static and an instance `Int?` property, a parameter, another such local, `HashMap<String, Int>.getOrNull`, a generic `T?` slot read for `T = Int`, `if`/`when` values with a null branch, and a nullable enum. Each case with null and with 0: `== null`, `??`, `!!` throwing on null, passing it on to an `Int?` parameter, reassignment, a loop, and across a suspension. Also that `q ?? 3`, `q == null`, `q!!` and a plain `Int` call stay plain. `hashMapGetOrNull` and `whenOnANullSubject` moved from `tests-v1-only` into `NullableEnumTests`: v2 passes them now. Needs amlc 0.16.0 (v1 or v2).

- **LoopLabelTests** (2026-11-17, #164). Labeled loops (`outer@ for (...)`, `break@outer`, `continue@outer`) as a program: nested for/while/loop/each in both forms, to and until ranges, three levels, jumps out of a try (the finally runs, and a plain break or continue there skips the rest of the loop body, which v2 ran), inside switch and when, a label named like a local or the loop variable, a lambda reusing the outer label, a suspend function that parks inside the loops, and an allocation count that shows the objects of the left loop bodies are released. Needs amlc 0.16.0 (v1 or v2).

- **Tests for nullable enums, and `tests-v1-only/`** (2026-11-17, #237). `tests/NullableEnumTests.aml` (13) runs `Color?` as a program under v1 and v2: null against a member whose value is 0, `!!`, `??`, fields (an uninitialised `Color?` is null), parameters, returns, data class fields, `when`, templates, other backing types (negative `Int`, `Short` from 5), `List<Color>`, `HashMap<String, Color>`, `Color[]` and a generic `T?` slot. Needs amlc 0.16.0. The cases v2 gets wrong for every nullable value type, `Int?` included (a null compared with a value, `x!!.f()`, `?.`, `getOrNull`, `List<Color?>`, `new Color?[n]`, statics, lambda captures, suspend), are in `tests-v1-only/tests/NullableEnumV1Tests.aml` (14), a package of its own outside `tests/` because one test v2 can't compile fails v2's whole run of `tests/`. Run it with `amlc test tests-v1-only -bt linux-x64 -lpp <folder with am-lang-core and am-tests>`.
- **Path style conversion in `Am.IO.File`** (2026-11-17, #380). `File.fromUnixPath("./data/../assets")` gives the host's form of a path written once in source: on AmigaOS, AROS and MorphOS `.` is `""`, `..` an empty part (`a/../b` is `a//b`) and a leading `/` the volume root `:`; on Windows and DOS the separators become `\`; on Unix the path is untouched. `toUnixPath` goes back. `fromAmigaPath`/`toAmigaPath` and `fromWindowsPath`/`toWindowsPath` do the same for those styles. A root the target style can't express (`Work:x`, `C:\x`, `\\server\share`) gives null. `File.convertPath(path, fromStyle, toStyle)` works between any two styles on any host, and `File.getPathStyle()` returns `PathStyleUnix`, `PathStyleAmiga` or `PathStyleWindows`, from a new `FileNativeHelper.getPathStyle` native. `..` is never resolved against the name before it. New PathStyleTests.
- **`TaskScheduler.runAsync<T>(threadType, work)`** (2026-11-14, #299). A suspend function runs `work` on a worker thread and resumes on its own thread with the result. The continuation stays on the caller's thread; only the work lambda crosses. The v2 compiler can't compile callers yet (#301).
- **`String.compareTo(other)`** (2026-11-14, #185). Byte-wise on the UTF-8 form, which is code point order; returns -1, 0 or 1, and a prefix sorts first. The compiler now rejects `<` `>` `<=` `>=` on strings, which compared addresses. Native in libc only; the other platforms' `String.c` are stubs.
- **`#noThrow` on 63 natives whose C can't throw on any platform** (2026-11-12, #183), checked against every platform's implementation. `tools/check-nothrow.py` repeats the audit and fails if a `#noThrow` native's C can throw.

### Changed

- **Build targets name `floatingPoint`** (2026-11-11, #247). amlc 0.16.0 no longer enables every feature for a target without `features:`, so core's targets list it.
- **Core uses `as T` instead of the obsolete `toT()` conversions** (2026-11-10). A build of core prints no warnings. `amlc test` prints 3, on purpose: they are the regression tests for #149 and #158.
- **Hex constants without type suffixes** (2026-11-10, #184). The min/max constants of Byte, Short, Long and the unsigned types take their type from the declaration (`0x80B` is now a compiler error).
- **`File.list()` joins through `joinPath`** (2026-11-17, #380). Listing `""` gives `name`, not the absolute `/name`. `joinPath` accepts a trailing `\` on Windows.
- **String index lookups use checkpoints** (2026-11-08). For a string with any non-ASCII character, `substring`, `indexOf` and `lastIndexOf` decoded the whole prefix on every call, so walking such a string by index was quadratic. A checkpoint every 32 UTF-16 units makes each lookup start nearby: v2's tokenizer got about 10 times faster on files with one non-ASCII character. ASCII strings are unchanged.

### Fixed

- **`File` on AmigaOS: `"."` is the current directory** (2026-11-17, #260). AmigaDOS has no `.` entry, and joins `DH0:` and `x` without a slash. The listing natives and `statEntry` now map `.` and `./` to `""` and join the AmigaDOS way.
- **A throw or return leaving a `suspend(cont)` body no longer frees the suspend state under the running frame** (2026-11-16, #298). New `Continuation.__claim`, which the compiler calls before that release.
- **Byte is `signed char` in the natives** (2026-11-10, #209). Plain `char` is unsigned on ARM and PowerPC, so `-128B` read back as 128 there.
