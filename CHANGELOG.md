# am-lang-core changelog

The runtime and standard library every AmLang program links. Core is released
with the compiler and carries the same version; changes that need a compiler
change are also in the compiler's `docs/releases/CHANGELOG.md`. Redmine numbers
are issues in the private tracker.

### Changed

- **AmigaOS and MorphOS: a thread that doesn't stop during an out-of-memory shutdown is removed after 10 s instead of being left running in the unloaded program** (2026-11-19, #446). Since #446 main waited `AMLC_OOM_JOIN_TIMEOUT_MS` for the other threads and then exited without the ones that never reached a stop point (a loop with no `receive`, `join`, `sleep` or `new`, or a thread stuck in an OS call). On the Amiga family that left an Exec task running code the exit had unloaded. Now the timeout there is 10000 ms (3000 elsewhere, unchanged), measured with `DateStamp` (a busy worker at main's priority stretches each one-tick poll to its whole quantum, so counting `Delay(1)`s ran long), and then `__amlc_remove_stuck_workers` (`core.c`) handles each worker that is neither `done` nor already removed: under `Forbid`, it finds the task in `TaskReady`/`TaskWait` by `tc_UserData == iso` (under `Disable` for the walk), checks `done` again, empties its `tc_MemEntry` and calls `RemTask`, then closes and unbinds its mailbox so no `Signal` goes to it, and prints `Thread 'busy' did not stop within 10 s; removed` (or `...; its task has gone` if it is in neither list). New `aisolate.removed`. What the task owned is leaked, never freed from main: its Process structure and stack (a DOS packet it had in flight may still be replied into them), its current-directory lock, and its isolate (heap, statics, mailbox, queued messages; the task's own handle is never dropped, so nothing frees the `aisolate`), and so its open files (still locked) and libraries. A join on it gives up as before; exit status stays 20. AROS (pthread-based `Thread.c`) is unchanged: pthread.library keeps its own bookkeeping of the task. Tests: `examples/OomShutdown/run.sh --amiga` now runs `busy` under amiberry (exit 20 with the message, about 11 s of emulated time for the whole run; then the program again, `Avail`, `Dir` and `Wait 30` in the same shell, all RC 0, no guru), the other twelve modes and the file checks still pass on AmigaOS, linux-x64 (and its ASan builds) passes as before, and a new `morphos-ppc-docker` target in the example builds and links for MorphOS (not run).
- **Breaking: out of memory shuts the program down instead of throwing `OutOfMemoryException`** (2026-11-18, #446). When the generated startup registers a jump target (amlc 0.16.0, `__amlc_oom_arm_main`), a failed allocation (`__allocate_object*`, `__create_array`, `__concatenate_strings`, or a native calling `__throw_out_of_memory_exception`) prints the class and `longjmp`s: main to its shutdown block, a worker to its teardown (`__amlc_worker_run`, now used by the libc, amigaos and morphos-ppc `Thread.c`), which sets `__amlc_shutdown_requested` and wakes main without allocating. Main's `__amlc_shutdown_begin` sets every other isolate's stop flag, wakes it and waits up to `AMLC_OOM_JOIN_TIMEOUT_MS` (3000). Threads stop at `Thread.receive`/`tryReceive`, `join` (now interruptible: a wait on a global condvar before `pthread_join`), `sleep` (in 50 ms slices; 5 ticks on the Amiga family) and `AMLC_STOP_POINT()` at every generated `new`. A failure inside the global lock, `Forbid` or `Disable`, or inside `Thread.send`'s deep copy (which swaps the isolate's object list), returns NULL to the runtime, which then takes the out-of-memory path once its state is back. Where no jump is possible in such a program (a worker's teardown, main before its static initializers have run) it prints and exits with the failure status instead of throwing an exception code built for 0.16.0 would drop. Without a registered target (code from v2) nothing changes: the exception is thrown as before. New test hook `Arc.failAllocationsAfter(count, sticky)`. `-DAMLC_NO_OOM_SHUTDOWN` builds without `setjmp.h`. Tests: `NoThrowAllocationTests`, and `examples/OomShutdown/run.sh`: ten modes on linux-x64, nine with `--amiga` under amiberry (not `busy`: on AmigaOS a task that never stops would run the unloaded program after the exit).
- **Build targets name `floatingPoint`** (2026-11-11, #247). amlc 0.16.0 no longer enables every feature for a target without `features:`, so core's targets list it.
- **Core uses `as T` instead of the obsolete `toT()` conversions** (2026-11-10). A build of core prints no warnings. `amlc test` prints 3, on purpose: they are the regression tests for #149 and #158.
- **Hex constants without type suffixes** (2026-11-10, #184). The min/max constants of Byte, Short, Long and the unsigned types take their type from the declaration (`0x80B` is now a compiler error).
- **`File.list()` joins through `joinPath`** (2026-11-17, #380). Listing `""` gives `name`, not the absolute `/name`. `joinPath` accepts a trailing `\` on Windows.
- **String index lookups use checkpoints** (2026-11-08). For a string with any non-ASCII character, `substring`, `indexOf` and `lastIndexOf` decoded the whole prefix on every call, so walking such a string by index was quadratic. A checkpoint every 32 UTF-16 units makes each lookup start nearby: v2's tokenizer got about 10 times faster on files with one non-ASCII character. ASCII strings are unchanged.

### Fixed

- **What frames skipped by an out-of-memory jump held is released when the thread or the program ends: an open `FileStream` is closed, an AmigaOS file lock goes** (2026-11-18, #447). Since #446 a jump skips the frames that would have released their locals, so those objects kept `reference_count >= 1`; the exit sweep frees only unmarked objects with a count of 0, and an object only a local held was on no list at all (`first_object` held property-referenced objects only). Their release hooks never ran, and on AmigaOS the file stayed locked after the program had exited. New global feature `releaseHeapOnExit` (`FEATURE_RELEASE_HEAP_ON_EXIT`; `core.h` turns it on by itself for AmigaOS, MorphOS and AROS, whose exit doesn't reclaim files and locks, and `-DAMLC_NO_RELEASE_HEAP_ON_EXIT` turns it off; elsewhere a build target lists it). With it, every object is on its isolate's `first_object` list from allocation to free (linked in the allocators, the fast lanes included, unlinked in `__deallocate_object`; a property count going 0 to 1 no longer links). New `__amlc_release_heap()`, called by `__amlc_isolate_teardown` and by main's generated shutdown (amlc 0.16.0), runs after the statics are dereferenced: the usual mark/sweep (all it does without the feature, with the worker's leak line as before), then, with the feature, the `TRACKOBJECTS` leak report (`Thread 'x' exited with N objects still allocated`, or `Main thread ...`, with up to 20 class names; printed before anything is zeroed, so real ARC leaks after a normal end stay visible), then it sets the code count of every object left to 0 (`reference_count` counts only code's references; property references are `property_reference_count`) and releases them: first those nothing else holds, through the normal ARC death, so a holder's release hook runs before its children go; then the cycles that remain, with every release hook run before any edge is dropped and the memory freed last. Immortal objects are skipped, and so is whatever the statics still reach (the emergency path jumps past their dereference). Natives that hold a code reference: an interface wrapper's reference to its implementation is given back before the release (and no longer counts as a root when marking, so a garbage cycle through one, such as TaskRunner, Thread and its Runnable, is still swept and not reported as a leak); `Continuation`'s release no longer resumes an orphaned suspended frame during this release (`aisolate.releasing_heap`), since that frame's locals are freed by the same pass; the other native releases touch only their own data or property children (`TempFile`, `SslSocketStream`), which the ordering covers. `__mark_root_objects` now also marks every object code still holds (`reference_count > 0`) and follows interface wrappers to their implementation, so the sweep no longer frees what such an object holds by property. Marking is iterative (a work stack on the isolate, recursion only if it can't grow) and deaths during the release are queued rather than recursed into, so a long list held by a skipped frame doesn't overflow the C stack (an AmigaOS task has little). The out-of-memory exception and its message are immortal now (any isolate may throw them). `GC.collect` sees code-held objects as candidates too; they are roots through their count, so what it reclaims is unchanged. Unconditional: the iterative marking and code-held roots, the immortal out-of-memory exception, the `Continuation` guard. Cost, only with the feature: an allocation-heavy loop (two objects and a string per iteration, -O2, linux) takes 0.66 s instead of 0.64 s (about 3%); without it, 0.63 s, as before. Tests: `HeapReleaseTests` (a nested stream in a cycle left open by a worker is closed when it ends and can be read back and deleted; a cycle through an interface; `GC.collect` keeps what a local holds), and `examples/OomShutdown/run.sh` with three new modes (`main-file`, `main-sticky-file`, `worker-file`: a nested stream held by locals, a `FileStream` in a cycle and a 20000-node list, open when the jump comes) plus AddressSanitizer + `TRACKOBJECTS` builds of every mode on linux-x64, with the feature (no use-after-free, no leak, `Allocated objects 2`) and without (no use-after-free; what skipped frames held stays allocated, e.g. `Allocated objects 23` in `main-file`); on AmigaOS under amiberry the files can be deleted after the program exits (with the old core, `Delete` fails with RC 5 and the worker's files can't be read back).
- **`File` on AmigaOS: `"."` is the current directory** (2026-11-17, #260). AmigaDOS has no `.` entry, and joins `DH0:` and `x` without a slash. The listing natives and `statEntry` now map `.` and `./` to `""` and join the AmigaDOS way.
- **A throw or return leaving a `suspend(cont)` body no longer frees the suspend state under the running frame** (2026-11-16, #298). New `Continuation.__claim`, which the compiler calls before that release.
- **Byte is `signed char` in the natives** (2026-11-10, #209). Plain `char` is unsigned on ARM and PowerPC, so `-128B` read back as 128 there.

don't have.
